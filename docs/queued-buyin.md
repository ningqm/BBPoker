# 随时补码

此文描述 0.21.0 公开实现；实际运行版本应由部署者独立核验。

- 开局前或两手之间补码：提交成功后立即到账。若恰好已发出下一手，服务器按实际收到请求时的阶段处理为待到账。
- 本手进行中，包括已弃牌、All-in 跑牌、等待参与的新入座玩家：可以提交补码，显示“待到账”，本手结束后到账，下一手可用。
- 待到账补码不改变当前手任何筹码、下注上限、边池、鱿鱼预留或结算。当前手的结束筹码、牌谱及输赢先固定，再应用补码，因此不会把补码算成盈利。
- 单次仍为 100–1000 BB、50 BB 的整数倍。累计带入上限同时检查已到账和待到账总额。重复请求使用同一操作编号不会重复排队或重复到账；不同补码请求可以累计。
- `players[].pendingBuyIn` 为待到账积分，默认为 0；`totalBuyIn` 仅含已到账带入。界面应使用两者之和计算累计限额，当前可下注筹码始终使用 `stack`。
- 仍在本手内安排离座会在手结束时生效；离座时未到账的补码取消，并留下金额为 0 的 `buyinCancelled` 记录及 `cancelledAmount`，说明取消金额且不计入带入或输赢。已安排离座时不能新增补码，先取消离座即可继续。
- 暂离不取消补码；到账不会擅自恢复参与。等待当前手的新入座玩家如果提前离座，立即取消待到账补码。
- 已经到账的补码正常参与离座／关桌的收回；关桌时仍未到账的补码取消。对进行中牌局的关桌仍要求先结束本手。
- 断线、重连、加密存档恢复保留队列。手牌结算与补码到账在同一持久化事务中执行；保存失败时筹码、队列、牌谱、流水、操作去重一并回滚，重试不重复记账。
- 每桌、每位玩家的已接受补码请求还会保留独立的持久收据，包含金额及排队／到账／取消状态。它不随普通操作缓存淘汰，也不因离座、关桌、队列清空或重启而丢失；同一操作编号即使改了金额也只认原请求。收据只在服务器保存，不下发给玩家。
- 已在本手内安排补码且结束时已到账的玩家，不会再收到空筹码的额外补码等待；仍保留结果展示至少 5 秒。
