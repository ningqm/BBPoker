# 发牌与数据边界

## 随机发牌

`src/poker.js` 的 `shuffleDeck` 用系统密码学随机整数执行 Fisher–Yates。洗牌输入不含账号、历史输赢、职业/新手标签或小游戏状态。小游戏只从积分栈扣除/结算，不修改引擎牌序。

服务器是唯一状态裁决者。客户端不能指定牌组、牌面或赢家。引擎中的显式 deck 参数仅供自动化测试使用，HTTP 接口不接受该参数。当前牌序连同行动状态加密持久化；断线和正常重启继续使用原牌序，不重洗。

## 可核验承诺

每个牌位置使用独立 32 字节盐，叶子为 `SHA256(handId:position:card:salt)`；补到 64 叶，父节点为 `SHA256(leftHex + rightHex)`（UTF-8 字符串）。根在首轮玩家主动操作前公布。

本人底牌、公共牌、主动亮牌和摊牌的公开牌可以获得路径证明；其他牌仅有不可反推的兄弟哈希，不公开盐、完整牌序或随机种子。

浏览器在本机保存最多 1000 手公开根承诺，不保存牌面或盐；同一 handId 出现不同根时会警告。首次接收可能晚于开局，清理浏览器数据也会丢失回执。回执仅代表本机首次所见，不是全局签名时间戳。

导出 JSON 可用 `node scripts/verify-export.mjs 文件.json` 离线验证。验证器检查版本、证明形状、位置唯一性、可见牌和位置对应以及根哈希。它不验证积分/行动历史的真实性、记录是否完整，也没有外部承诺回执，因此无法发现攻击者重写整副牌和整套证明。

承诺保证的是**与已经看到的根保持一致**。它不单独证明初始抽样公平，也不约束恶意运营者事先反复挑牌、选择性中止、给不同人不同根或偷偷部署不同程序。没有实现零知识证明、多方洗牌或独立审计。

## 弃牌保密

实时状态、事件流、历史详情、回放和导出均按请求者身份重新投影。本人可看自己的牌；其他人只能看主动公开/正常摊牌的牌。历史中的未知牌为 null 或 `??`，不只是界面盖一张牌背。公开证明也严格遵循同样权限。

公开展示、主动亮牌不可撤回。不要把自己的找回码交给别人：它可用于重设密码并访问本人的记录；未绑定账号的旧恢复码可直接登录。

## 存储和权限

- 完整状态以 AES-256-GCM 保存于 `data/table.enc`；密钥单独放在同目录的受限文件中。目录权限 0700、文件 0600（适用支持这些权限的系统）。
- 写入先落临时文件、fsync 后替换；存储失败的操作会回滚，不对外宣布成功。
- 密钥缺失且已有存档时拒绝启动，不另生成密钥覆盖旧数据。
- 密码使用独立随机盐和异步 scrypt 保存哈希；登录令牌和找回码也只保存哈希。浏览器保留有期限的登录令牌，不保存密码；新找回码只在生成时显示。没有第三方统计脚本/CDN。
- 改密或找回会撤销旧会话并关闭其牌桌事件流；找回码轮换后旧码不可再次使用。详见 [账号说明](accounts.md)。
- API 禁止缓存；Service Worker 只缓存公开静态壳，离线时无法对局。
- 手牌 ID、行动序号和操作去重 ID 防止旧请求或重试误作用于另一手/另一轮。亮牌绑定特定手牌。

**加密不等于运营者不可见。** 服务器内存中有明文牌组，拥有服务器文件和密钥的管理员可以解密。密钥与密文一起被复制也能解密。若要防范服务器管理员，需要另一套多方密码学设计；本版本没有这个能力。公网部署必须使用 HTTPS，避免恢复码和本人牌谱被链路窃听。
