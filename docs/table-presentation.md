# 牌桌展示节奏与牌型

此文描述 0.22.0 公开实现；展示不改变发牌顺序、牌力比较或结算规则。

## 行动与发牌

- 首次发牌预留 1100 毫秒。普通下注轮最后一次行动先保留 900 毫秒，再由服务器真正抽取下一街牌；翻牌再预留 900 毫秒、转牌和河牌各 700 毫秒后，才开放完整的 20 秒行动时间。
- 等待换街时不提前抽牌、不提前追加下一街的日志或校验证明。`hand.transition` 包含 `kind`（`street`／`showdown`／`award`）、`nextAt` 以及摊牌是否已展示的 `revealed`。期间没有行动者或行动倒计时；普通换街保留原本街下注，跑码与摊牌阶段撤掉已入池的重复下注条。
- 普通河牌跟注／过牌收尾：保留最后动作 900 毫秒，再公开未弃牌选手的底牌；展示 700 毫秒后才派奖。最后一人弃牌则保留 650 毫秒再收池，不强制公开任何底牌。
- All-in 首次等待 1800 毫秒，翻牌三张同时揭开，再分别间隔 1500 毫秒揭开转牌、河牌，不叠加普通换街等待。已在翻牌或转牌时锁定的牌局只揭开剩余街；旧版只揭开一两张翻牌的存档恢复后一次补齐翻牌，不重复烧牌。最后一张河牌真正翻出后额外展示 700 毫秒，再结算派奖。
- `hand.actionReadyAt` 与 `hand.turnStartedAt` 为服务器毫秒时间。等待期间 `actions.canAct=false`；到时服务器只发布一次更新，同一条街换到下一位玩家不会重复等翻牌。
- `actions.turnAvailable` 记录规则引擎层面是否轮到当前用户，帮助界面保留按钮位置。客户端必须使用 `canAct` 控制操作可用性，不能把这个字段当成跳过展示间隔的授权。
- 陪练机器人同时检查 `actionReadyAt`，不会因旧快照残留的 `canAct=true` 提前行动。
- 发牌完成前服务器也会拒绝直接 API 提交的行动与时间牌请求，不扣筹码、不扣时间牌。到点后第一位玩家获得完整 20 秒；同街的后续玩家按原有顺序接续。
- 所有待推进阶段及截止时间随加密存档保存。恢复或迟到的定时器只推进当前一步，下一阶段从实际公布时刻计时，不会追赶并跳过发牌、摊牌或结果停留。

## 每手之间的停留

- 正常摊牌结束后至少停留 5 秒。
- 提前弃牌结束时先补看剩余公共牌，然后从补看牌实际公布的时间起停留 5 秒。迟到的定时器不能把补看和下一手在同一轮更新里一起完成。
- 补码机会仍为同一手的一次共享额外 5 秒；需要补看时，补码窗口整体顺延到结果停留之后。
- 暂停、重连、恢复存档不重复结算、不重复发牌；已经公布的结果时间会保存，持续查询不会无限推迟下一手。

## 主池、边池与牌型

- `hand.pots` 是可展示的匹配筹码分层，包含 `amount` 和 `eligibleIds`；`hand.uncalledBets` 为尚未跟注部分，包含 `playerId` 和 `amount`。两部分相加等于总投入 `hand.pot`。
- 展示计算只作用于手牌副本，不退款、不结算真实筹码。实际结算与历史牌谱继续使用原有权威结算结果。界面可把可领奖玩家集合相同的层合并展示，避免把弃牌死钱误叫作额外边池。
- `players[].handCategory` 按观看者隔离：本人从拿到底牌起看到当前牌型，其他人仅在两张底牌公开且未弃牌时可见。只使用真正已发出的公共牌；本人弃牌后按弃牌日志街道冻结当时牌型，缺少旧日志时保守不显示；补看牌不参与。

## 自己的牌型与升级

- 普通对局、All-in 跑码均显示自己的当前牌型；翻前为高牌或一对，真实公共牌发出后重新计算。
- 同一手公共牌增加且牌型等级提升时，标签在翻牌正面可见的 260 毫秒后换色、轻微放大，再归位；同类牌只提高点数不播放升级。
- 用最初事件时间恢复动效进度，聊天和倒计时刷新不重新播放；初次进入、重连、后台回归、换身份、下一手和关闭动效均静默。弃牌和补看不会产生假升级。
- 筹码改用选定的② Joma86 整摞推进实录，素材和授权见 `chip-sound-source.md`。语音采用同一男声，All-in 使用中文“凹印”读法；视频仅作参考，未提取商业游戏音轨。

## 当前牌型配色

- 高牌雾灰、一对薄荷绿、两对天蓝不变；三条改丁香紫，顺子改冰青横向高光，同花改明艳玫粉。
- 葫芦同步改深紫白字，与同花区分；四条保持亮橙。同花顺采用亮金色；A 高同花顺同样显示“同花顺”并使用相同标签，不再单列皇家名称。
- 不新增图标或持续闪烁，标签尺寸、升级动效和牌型规则保持；只是调整颜色、光泽与文字阴影。
- 九类标签按牌型区分；颜色只表达牌型类别，不代表胜率或必胜。A 高同花顺仍按最高点数参与比较，只合并显示名称，不增加或删除牌力等级。
- All-in 最终采用用户确认的中文“凹印”读法（同一男声），筹码采用已选②实录；详情和音频哈希见 audio-assets.md。


## 直接下注与稳定操作

- 快捷尺度显示实际下注／加至总额，点击后直接提交。竖向滑条只选择金额，面板按钮提交；拖到顶为精确 All-in，方向键按 1 BB 调整。
- 按钮绑定房间、手牌、行动序号、行动者和报价；过期报价、断线、同步与提交中的按钮不可操作。相同轮次、相同报价的节点保留，避免刷新吞掉正在发生的点击。
- 等待发牌与实际可行动分开显示。恢复页面、输入法退出、弹窗切换与迟到通知只能触发重新同步，不在客户端自行授权行动，不自动重复提交。

## 紧凑牌桌

- 房间标题下显示盲注、时间和小游戏摘要；详情通过本场入口查看。桌内优先保留底牌、公共牌、筹码和行动倒计时。
- 真正全下且余码为零的玩家在原余额行显示 All-in，其他人保持余额。下注仍开放时显示每人的本街金额；进入跑码或河牌摊牌后移除这些金额条，已入池金额不变。结算后恢复余额与收池状态。
- 座位百分比是主池权益，平分按份额计入，不能替代不同边池的权益。总底池有计算结果时可点击查看各层参与资格与权益，不再额外占用一行“胜率详情”。
- 每位实际收池者获得金额、金色座位轮廓和筹码飞入效果；按实际派彩而非净盈利显示，未跟注退款不产生收池动效。聊天刷新沿用原始动效时间，重连不补播。
- 键盘、聊天和表单根据可视窗口安排；窄屏保留可滚动空间。几何回归样本来自合成牌桌，不包含线上用户或真实牌谱。视口模拟不替代真机触摸、系统音频与后台恢复验证。

## 声音与回放

- 过牌使用原创短促双敲桌声；其他动作使用现有短语音。派奖使用已选筹码录音，平分和边池不叠加多次收池声。静音、断线、后台与首次加载不补播历史动作。
- 旧版逐张跑码事件在回放中还原完整翻牌、转牌和河牌；换街清理上一街下注显示，原始结算和隐私权限不改变。
