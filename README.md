# BBPoker

BBPoker 是供朋友在线同桌玩的德州积分游戏。此仓库包含可独立运行的网页和 Node.js 后端：支持多张独立牌桌，每桌 2–9 人入座，手机和电脑浏览器连接同一个服务器。没有充值、提现、抽水或现金结算。

公开仓库：[ningqm/BBPoker](https://github.com/ningqm/BBPoker)。

当前源码版本为 **0.12.0**。线上网站是否使用此版本，应由部署者另行核验。

## 0.12.0：中途入桌、返桌与鱿鱼连续性

- 中途新入座默认等待自然大盲，也可选择补盲参与后续合适位置。补大盲是有效下注，抵翻前跟注；需要补的小盲进入底池但不抵跟注。特殊位置自动等过庄，实际发牌时才收取，自然大盲不会与入桌大盲重复收取。
- 断线、暂离、离座和换座沿用同一账号的漏盲记录，最多记一次大盲和一次小盲。同手断线重连不收费。等待者不被强制放到小盲；全员等待而无法开牌时，需一人改选补盲。炸弹池遇到待处理入桌时先发普通手。
- 鱿鱼固定原轮名单。缺席者从下一手起不发牌、不持续烧盲，已有标记、预留和结算责任保留；剩下符合条件的原轮玩家达到两人就继续鱿鱼，不切换普通桌。原轮返回不重复收取预留，中途新人等待下一轮。
- 只剩一人没有标记时正常结轮；多人没有标记且都无法参与、其余可继续者均已有标记时，当前手结束后留 5 秒返回缓冲，再按实际标记结轮。K 位有标记者各收 M×单位，M 位无标记者各付 K×单位；无标记者之间不互相付款，剩余预留退回。缓冲内有效返回会取消待结轮，全部离线不会触发这项结轮。
- 原轮不足两人可发牌时等待返回、补码或完成补盲选择。持续 90 秒后在线原轮参与者可在手后提前结轮；本场到时且能够继续则打完原轮，不能继续则在恢复窗口后结清散桌。无人获标时无人支付。已结轮不能靠重连撤销。
- 新一轮仅在候选玩家都能实际拿牌时收取预留，避免新人尚未拿牌便负担鱼局结算。补盲日志纳入回放、PHH 导出和积分对账，不计为自愿入池；独立鱿鱼流水按轮次去重，不虚增手数或跑牌期望。

完整家规、等待与返桌边界见 [多牌桌与鱿鱼轮次](docs/room-lifecycle.md) 和 [玩法规则](docs/rules.md)。这些是 BBPoker 的朋友局约定，不声称复制 WPK 的未公开细则。

## 0.10 新增

- 已落座玩家可以向同桌朋友泼水、扔番茄、摸头或碰杯；服务器校验身份、目标、冷却和频率。全下时增加轻量娱乐效果，关闭动画后仍可正常操作。
- 五个固定公共牌位置在未揭开时只显示牌背，发牌后翻面；效果不预加载未来牌面，不修改行动倒计时。
- 提前弃牌结束后自动补看剩余公共牌，使用本手原牌堆并遵守烧牌顺序。补看不公开未亮底牌，不改变赢家、盈亏、全下期望或其他统计。
- 补看单独保存；回放只在结算帧展示，拖回历史行动即隐藏。浏览器和离线导出验证器都检查已展示补看牌的承诺证明；PHH 保持真实牌局原样。

互动、补看时序和官方设计参考见 [牌桌互动与结算后补看](docs/table-entertainment.md)。

## 0.9 新增

- 两家或多家全下且全部下注结束后，公开仍参与争池的底牌并显示胜率，每揭开一张公共牌更新一次；尚有两家能够继续争夺边池时，不提前亮牌。
- 全下计算按主池、边池资格分别处理平分与零头。小组合使用精确枚举，翻牌前默认模拟 20,000 次并标注估算；胜率计算不读取真实牌堆或弃牌底牌，也不控制发牌。
- 个人页与牌桌内均可查看手数、净积分、VPIP、PFR、RFI、3B/4B/5B、摊牌及 BB/100 等指标，显示样本与机会分母；支持近 1/3/7/30 天、全部、自定义日期、牌桌和最近 N 手筛选。
- 全下跑牌比较同一批手的起点期望净盈利、实际净盈利与偏差，支持曲线和手牌复盘。只使用已经保存起点的有效样本；旧牌谱缺少起点时明确显示覆盖不足，不根据最终牌面伪造期望。

抽样胜率具有误差，跑牌偏差不预测下一手，也不能证明发牌公平。此版仍需信任服务器运行者。具体指标分母、计算边界和参考资料见 [个人数据与全下跑牌](docs/analytics.md)。

## 本机启动

需要 Node.js 22 或更高版本。网页和服务端没有第三方运行依赖，无需执行 `npm install`。

```sh
npm start
```

打开 [http://localhost:8787](http://localhost:8787)。注册账号和密码，私下保存找回码；创建牌桌并入座，通过“邀请”复制链接给朋友。至少两人入座后由房主开始第一手，此后每手结束约 5 秒自动继续，补看尚未完成时等展示结束；房主可以暂停。`localhost` 仅指当前设备，异地联机需要部署统一的 HTTPS 网站，见 [部署说明](docs/deployment.md)。

首次启动会创建 `data/`，其中包含加密存档与密钥。**不要将数据目录、密钥、真实环境配置或导出的私人牌谱提交到仓库。**

## 功能

- 账号密码注册、登录、修改密码、找回码重置与会话撤销；可修改昵称、随机分配 6 张 AI 默认头像或上传并裁剪自定义头像，没有短信或邮箱服务。
- 大厅与公开/邀请入桌、直接带入、补码、暂离、离座、转交房主和结束本场。带入以大盲数量（BB）配置，默认 20–200 BB，可设置无上限，无需审批。
- 无限注德州、主池/边池、平分和零头分配、未跟注退款；可选鱿鱼及单牌面炸弹池。蘑菇已移除，旧记录与退款保留。
- 建房常用项默认展开，玩法、人数、带入范围与时间牌收进高级设置；可读取已参加过的旧牌桌配置后微调，新房不继承旧邀请、成员或计时状态。
- 常用盲注和时长预设，默认盲注 5 / 10、思考 15 秒、本场 1 小时。第一手开始计时，到时打完当前普通手或延长至原鱿鱼轮完成后收桌，无法恢复则进入限时结清窗口；最后 5 分钟不新开小游戏。
- 默认每半小时重置 3 张时间牌，每张延长 30 秒，数量和时长可配置；服务器保存剩余时间牌和计时状态。
- 牌桌与行动区保持在同一屏，聊天使用抽屉，牌谱、本场详情及菜单使用弹窗。发牌、下注、结算有轻量动效和可关闭的本地合成音效。
- 加注滑杆前段细调、后段加速，保留精确数字输入和常用额度快捷键。
- 每手结束约 5 秒后由服务器自动发下一手，补看最后一张后至少停留 1.3 秒；条件不足或全桌离线时等待，房主可暂停。断线重连与服务器行动倒计时保留，重启不重新洗牌或重置有效行动时间。
- 放大牌面数字与花色，更新标签页及主屏幕图标；用独立版本地址处理旧图标缓存。
- 对局按整场牌桌展示本人输赢，点开可查看每位玩家的德州、小游戏及合计净积分。牌谱和对局支持日期、结果、玩法/状态、牌桌、收藏及搜索筛选，全量筛选汇总不受分页影响。
- 个人牌谱、收藏、自动播放回放（暂停、0.5–4 倍速、拖动进度）、JSON/TXT/CSV/PHH 导出与生涯统计。切后台暂停回放，关闭或换账号销毁计时器。
- 记录页的输赢、玩法及收藏筛选不自动用于导出；导出按本人参加过的手牌与单独选择的日期范围处理。
- 实时、历史、回放及导出均按玩家身份过滤，其他人的未公开底牌不会通过正常接口下发。

详细说明：[玩法规则](docs/rules.md)、[账号](docs/accounts.md)、[聊天与回放](docs/social-replay.md)、[PHH 牌谱](docs/hand-history.md)。

## 发牌与隐私边界

洗牌使用 Node.js `crypto.randomInt` 与 Fisher–Yates；洗牌函数不读取账号、历史输赢或玩家画像。小游戏不改变牌序。服务器在每手开始固定牌序，并提供本人可见牌的承诺校验材料。

**仍需信任服务器及网页运行者。** 服务器进程知道完整牌序，拥有服务器文件和存档密钥的人可以解密数据。承诺核验只能检查可见牌是否符合承诺，不能证明初始抽样公平、线上程序与公开源码相同，或管理员无法查看底牌。本项目没有多方加密洗牌、零知识公平证明或第三方公平性认证。详见 [发牌与数据边界](docs/fairness.md)。

## 检查

```sh
npm run check
npm test
node scripts/verify-export.mjs --help
```

默认测试使用 Node 内置测试框架及独立临时数据，不连接正式站点，不需要安装原生客户端依赖。可选的 PokerKit 交叉验证只有显式设置独立 Python 解释器时才运行，步骤见 [PHH 牌谱说明](docs/hand-history.md)。

离线导出验证器可核验一份 BBPoker JSON 牌谱内的可见牌与承诺是否一致，不联网、不打印底牌；它不验证牌谱真实性、完整性或服务器是否公平。

本仓库公开测试代码；请以自己在对应版本上实际运行的结果为准。测试通过不是独立审计，也不能替代真实手机、异地网络和备份恢复验收。

## 部署与数据

支持直接运行 Node 或构建 Docker 镜像。必须只运行一个写入实例；当前每次操作保存整份加密存档，不支持多个进程共享写入。更新程序不应替换数据或密钥。自定义头像独立加密存入数据目录的 `avatars/`，备份须包括 `table.enc`、`key` 和 `avatars/`。程序、数据分目录不能防止磁盘损坏或误删，需要部署者另行配置服务器之外的私密备份并验证恢复。

仓库不包含线上账号、用户记录、环境配置、云资源标识或部署实录，也不包含正式 App 安装包。真实设备兼容性由部署者按实际使用环境验收。
